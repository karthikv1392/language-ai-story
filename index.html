01

The McCulloch‑Pitts Neuron

In 1943 — decades before "neural network" was even a phrase — Warren McCulloch and Walter Pitts proposed the simplest possible model of a neuron. No training, no real-valued weights adjusting over time, not even learning: just binary inputs, a weighted sum, and a threshold. If the sum clears the threshold, the neuron fires (outputs 1). If it doesn't, the neuron stays silent (outputs 0). That's the whole model.

output  =  1  if  (w1x1 + w2x2 + …) ≥ threshold   else  0

McCulloch and Pitts' point wasn't really biology — it was that this one trivial device, wired up with the right fixed weights and threshold, can compute logic. Pick a gate below, flip the inputs, and watch the neuron decide for itself.

02

Perceptron

The McCulloch-Pitts neuron could compute AND — but only because we set w1=1, w2=1 by hand. Fixed weights don't scale: someone has to hand-solve every new gate. In 1958, Frank Rosenblatt asked: what if the neuron started knowing nothing, and learned those weights itself, just by seeing examples and getting nudged when it's wrong?

wi  ←  wi + (target − prediction) × xi

Same firing rule as the McCulloch-Pitts neuron. The only difference: every time it's wrong, each weight gets nudged toward the answer. Press "Train step" to feed it one example at a time — it's learning AND from scratch.

Multi‑Layer Perceptron

A single perceptron draws exactly one straight line. Some patterns can't be split by any straight line at all — the classic example is XOR. Stack a hidden layer of neurons in between, and the network can bend that line into a shape. (How do you actually find the right weights for a stack like this? That's next.)

Whatever's outside the window is invisible — permanently. A bigger window just means more fixed-position weights, not real flexibility: a sentence one word longer than your widest window still breaks it. An RNN fixes this with one set of weights, reused at every step, carrying a memory instead of a window.

04

Backpropagation

A perceptron can only learn things a straight line can separate. Stacking neurons into layers, as we just saw, breaks past that — but the perceptron's simple nudge rule has no idea how to update weights buried inside a hidden layer. Backpropagation solves that: the same learn-from-mistakes idea, generalized with calculus so the correction reaches every layer, not just the last one.

The idea has three parts. Forward pass: run the input through the network to get a prediction. Loss: measure how wrong that prediction is. Backward pass: use calculus — the chain rule — to work out exactly how much each weight contributed to that error, then nudge every weight a little in the direction that reduces it. Do this enough times and the weights converge on values that actually work.

Embeddings

Every network so far has computed on numbers. But words aren't numbers — feed a network the word "cat" directly and it has nothing to multiply. Hence: an embedding, a lookup table that turns each word into a fixed list of numbers, placed so that words used in similar ways end up near each other.

06

How RNNs Read a Sequence

Multi-layer networks can only ever see a fixed window of words — make the window bigger and you just get more fixed-position weights, not real flexibility. The recurrent neural network (RNN) fixes that: one set of weights, reused at every step, carrying a running memory forward instead of a window. Let's watch one actually do that, one step at a time.

At every step, an RNN combines two things: the current word (as a vector) and whatever it remembers so far — its hidden state — into a brand new hidden state. That new state becomes both this step's output and next step's memory:

ht  =  tanh( xt · Wx  +  ht−1 · Wh )

There's no shortcut: computing step 4 requires step 3's result first. Nothing here is trained (same honesty as the rest of this page — the weights are fixed and random), but the mechanism is exactly right. Press "Next word" and watch the hidden state actually change, number by number.

This is it — everything about the sentence you just read has to live inside these 8 numbers now. Nothing else survives to the next step. That squeeze is exactly the problem attention was invented to solve.

07

Encoder‑Decoder

An RNN can read a sequence and keep a memory of it — but some jobs need to turn one sequence into a completely different one, like translating English into Italian. A plain RNN has no natural way to do that. Hence: the encoder‑decoder. One RNN (the encoder) reads the whole input and hands off a single summary vector. A second RNN (the decoder) starts from that handoff and generates a brand new sequence, one word at a time.

Source (English) — the encoder reads this
Target (Italian) — the decoder writes this

That single handoff vector is a real bottleneck — the decoder has to work from one fixed summary of everything the encoder read, no matter how long the input was. What if the decoder could look back at every encoder step instead of just the last one? That's exactly what attention adds, coming up next.

Self-Attention

Before a model can understand a sentence, every word needs to figure out which other words to pay attention to. Self-attention is the mechanism that computes this, for every word, all at once.

Query

What this word is looking for. Every word asks a question.

Key

What this word has to offer. Every word advertises an answer.

Value

What this word actually hands over, if another word decides to attend to it.

A word's Query is compared against every word's Key. A strong match means a high score — after softmax, that becomes an attention weight: how much this word borrows from that word's Value. Click a word below and watch its weights.

Where does the embedding come from? Every word is looked up in a table and comes back as a fixed list of numbers — its embedding. In a real model this table is learned during training, so words used in similar ways end up with similar-looking lists of numbers; this demo just uses fixed, reproducible numbers per word instead, since nothing here is actually trained.

Where do Query, Key and Value come from? Each is that same embedding, multiplied by its own matrix of learned weights (Wq, Wk, Wv). "Multiplied by a matrix" just means: every output number is a weighted sum of every input number. Same input, three different matrices, three different vectors out. 09

Before Transformers

Attention didn't start with Transformers. It was invented in 2014–15, bolted onto the encoder-decoder RNN we just built, to fix exactly the bottleneck it has: the decoder only ever gets one fixed handoff vector, and every step has to wait for the one before it — no shortcuts, no jumping ahead. Transformers (2017) then asked a bolder question: what if we kept the attention and threw the RNN away entirely?

The 2014–15 fix: don't throw the earlier states away

Bahdanau's and Luong's insight: keep every hidden state, not just the last one. While producing each output word, compute a score between what you're generating now and every input hidden state, softmax those into weights, and blend accordingly. That's the same score → softmax → weighted-blend recipe from self-attention — just comparing a decoder step against another sequence's hidden states, instead of a word against words in its own sentence. That distinction has a name: this is cross-attention (one sequence attending to a different one), not self-attention (a sequence attending to itself). Transformers use both.

A classic example of why this mattered: word order isn't the same across languages. Translating "the black cat" into Italian gives "il gatto nero" — the adjective jumps from before the noun to after it. A model that could only align word 1↔1, 2↔2, 3↔3 has no chance. Attention just learns wherever the alignment actually is:

Row = Italian output word, column = English source word. "nero" lights up "black" — two positions away, out of order — because attention doesn't care about position, only relevance.

2017: what if attention is all you need?

The Transformer paper kept the score → softmax → blend idea, then made two changes that mattered more than anything since: it dropped the RNN completely, and it used attention within a sequence too (self-attention, covered earlier) alongside the cross-attention link between encoder and decoder. The payoff is best seen as a question: how many steps does information need to travel from word 1 to word 6?

RNN: word 1's information has to pass through every hidden state in between. Five hops, computed strictly in order — and the more words in between, the more chances for it to fade.

Transformer: word 1 attends to word 6 directly. One hop, regardless of distance — and every word's attention is computed at the same time, not one after another.

That parallelism is also why Transformers train so much faster on GPUs: an RNN's word-by-word dependency can't be parallelised across a sequence, but a Transformer's attention can.

The price of dropping the RNN: order has to be added back in

An RNN never had to be told what order words came in — it read them in order, one at a time, so order was baked into the process itself. A Transformer looks at every word at once, and attention on its own can't tell "the cat sat" from "sat the cat": it only compares what each word is, never where it sits. So before attention runs, every word's embedding gets a second vector added on top of it — a positional encoding: a fixed pattern of numbers that depends only on the word's position (1st, 2nd, 3rd…), never on what the word actually is. Position 2 gets the exact same pattern whether the second word is "cat" or "jumped".

The original Transformer paper builds that pattern from sine and cosine waves at different frequencies per position — not because the wave shape is special, but because it gives every position its own distinct, structured fingerprint. 13

Instruction & Chat Tuning

A raw foundation model just continues text — it was only ever trained to predict the next word, so it treats a question as something to keep writing, not something to answer. Fine-tuning fixes that in two stages. Instruction-tuning: train on (instruction → response) pairs, so it learns to answer instead of continue. Chat-tuning: train further on multi-turn conversations (often refined with human feedback, called RLHF), so it learns to be genuinely helpful, not just correct. This two-stage recipe is roughly how a base model like GPT becomes an assistant like ChatGPT.
